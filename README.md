# なし栞 + なしスタジオ

伺か（SSP）用の **栞（SHIORI）** と、その栞を使うゴーストを **Scratch のようにブロックを積んで作れるアプリ** の一式です。
どちらも Windows ネイティブ（C++ / MSVC）で、ランタイムのインストールは要りません。

| | |
|---|---|
| **なし栞 `nashi.dll`** | SHIORI/3.0 の DLL（32bit・静的CRT）。会話は C++ ではなく `ghost.json` に入ったブロックで書く。 |
| **なしスタジオ `nashi-studio.exe`** | ブロックエディタ本体（64bit・単体で動く1ファイル）。自前のウィンドウに WebView2 を埋め込んだネイティブアプリ。UI も栞も exe の中。 |

---

## つかいかた

### 1. 起動する

**`nashi-studio.exe` をダブルクリック** するだけです。

* 自分のウィンドウが開きます。ブラウザは起動しませんし、アドレスバーもタブもありません。
* ウィンドウを閉じればアプリも終わります。保存していない変更があれば確認します。
* ウィンドウの位置と大きさは次回起動時に復元します。
* 二重起動しても増えません（すでに開いているウィンドウが前に出ます）。

**ポートは開きません。** 画面からの要求は WebView2 の中で受け取って、そのまま exe の中で処理しています。
外に出る通信もしません（SSP と話すときだけ `127.0.0.1:9801` へ接続します）。

> 画面表示に **Microsoft Edge WebView2 ランタイム**（Windows 11 標準搭載）を使います。
> 万一入っていない場合は、起動時に案内と配布ページへのリンクを出します。

### 2. ブロックを組む

1. 左の **イベント** から「起動したとき」などをキャンバスにドラッグします。
2. その下に **セリフ** の「◯◯が □□ と話す」をつなげます。
3. 右の **ためす** タブの ▶ で、しゃべる様子とさくらスクリプトを確認できます。
4. 立ち絵は **ゴースト** タブの「立ち絵の画像」で、用意した PNG を番号ごとに割り当てられます
   （えらばなかった番号は、指定した色でかんたんな立ち絵を自動生成します）。
5. **チェック** タブに、空のセリフ・無い変数・行き先のない選択肢などが出ます。
   赤い数字が付いていたら、そこを直してから書き出してください。項目をクリックすると
   その場所までキャンバスが動いて、ブロックが光ります。

### 3. SSP に入れて動かす

**書き出し** タブの「**SSP に入れて動かす**」を押すだけです。

* SSP の場所（`ssp.exe`）を自動で探します。動いていれば実行中のプロセスから、
  止まっていれば `C:\ssp` などのよくある場所から見つけます。
  見つからないときは、同じ画面の欄に `ssp.exe` のパスを入れて「この場所を使う」。
* SSP の `ghost\` フォルダへ直接書き出し、そのまま **SSP のゴーストを切り替えます**。
* すでにそのゴーストが動いていた場合は、書き出したあと **栞だけ読み込み直します**（切り替え無し・一瞬）。
* SSP が止まっていれば「SSP を起動」で立ち上げられます。

配布用にまとめるときは、同じ画面の「.nar を作る」。
できた `.nar` を SSP のウィンドウにドラッグ＆ドロップするとインストールできます。

> SSP を動かしたまま書き出し直した場合、栞が数秒以内に `ghost.json` を読み直すので、
> 手動でのリロードも基本的に要りません。

### 4. 動いているゴーストで試す（SSTP 連携）

**ためす** タブに SSP の接続状態が出ます。つながっていれば:

* **SSPでしゃべらせる** — いま選んでいるトークを、**デスクトップで動いている本物のゴースト**に
  しゃべらせます（エディタ内のプレビューではなく実機確認）。
* **イベント送信** — 選んでいるイベント（`OnMouseDoubleClick` など）を SSP に投げて、
  入れたゴーストが実際にどう反応するかを確かめます。
* **話しかけてみる** — 他のゴーストのふりをして、動いているゴーストに話しかけます。
  「話しかけられたとき」のブロックを選んでいれば、その相手・内容で話しかけるので、
  しぼり込みが効いているかそのまま確かめられます。

内部では SSP の **SSTP**（`127.0.0.1:9801`）に `SEND` / `NOTIFY` / `EXECUTE` /
`COMMUNICATE` を送っています。
SSP 側で「SSTP を受け付ける」設定が有効（既定でオン）になっている必要があります。

絵を用意していない場合は、簡単な立ち絵（サーフェス 0/1/2 と 10/11/12）を自動生成します。
自分で描いた絵に差し替えるときは `shell/master/` の PNG を置き換えてください。
既にあるシェル画像は、書き出し直しても上書きされません。

### 保存される場所

`nashi-studio.exe` と同じフォルダに作られます。

| | |
|---|---|
| `projects\` | プロジェクト（作りかけのブロック）。初回起動時にサンプルが入ります |
| `output\` | 書き出したゴースト（書き出し先を変えていない場合） |
| `nashi-studio.json` | 最後に開いたプロジェクト・書き出し先・ウィンドウの大きさ |
| `webview-data\` | WebView2 の作業フォルダ（消しても再生成されます） |

exe のとなりに `nashi.dll` を置くと、埋め込みのものより **そちらが優先** されます（栞を作り直したときに便利）。

## ビルド

Visual Studio の「C++ によるデスクトップ開発」が入っていれば、これだけです。

```powershell
.\build.ps1            # 栞(32bit DLL) → スタジオ(64bit EXE)
.\build.ps1 -Test      # 栞のテストホストも作り、一致テストも走らせる
```

`-Test` を付けると、最後に 2 つのテストが走ります。

| | |
|---|---|
| **一致テスト**（`shiori\test\parity`） | `ui\js\sim.js`（プレビュー）と `shiori\src\interp.cpp`（本番）は同じ規則を二重に書いているので、同じ `ghost.json` を両方に流して、出てきたさくらスクリプトが一致するか見くらべます |
| **ふるまいテスト**（`shiori\test\behavior`） | 栞だけが持っている判断 — 同じイベントに複数あるときどれを選ぶか、ブロックが無いときの既定の反応、`OnClose` の `\-`、「◯秒ごと」の間引き、なでなでの生成、通信の届け先 — が期待どおりか |

この 2 つだけ **Node.js** を使います（入っていなければ飛ばします。アプリの動作には要りません）。
ブロックやふるまいを足したら、`shiori\test\` の材料と期待値もいっしょに直してください。

個別に作るときは `shiori\build.ps1` / `studio\build.ps1`。
スタジオのビルドでは `studio\tools\embed.ps1` が `ui\` 以下と `nashi.dll` を
リソースにまとめ、exe に埋め込みます（UI を直したら再ビルドしてください）。

WebView2 の SDK は `studio\third_party\webview2\` に入れてあります（ヘッダと静的リンク用の
`WebView2LoaderStatic.lib` だけ。MIT ライセンス）。ダウンロードは不要です。

### スマートアプリコントロールでブロックされたら

Windows 11 の **スマートアプリコントロール**（既定でオンの環境があります）は、
署名がなく実績のない exe をブロックすることがあります。ビルドしたばかりの
`nashi-studio.exe` が「アプリケーション制御ポリシーによってブロックされました」と
言われた場合は、次のどれかで対応してください。

1. **少し待ってもう一度実行する** — 判定が確定すると通ることがあります（確実ではありません）。
2. **コード署名する** — 公的な認証局のコード署名証明書があれば確実です。
   ```powershell
   .\studio\build.ps1 -SignThumbprint <証明書の拇印>
   ```
   自己署名証明書ではスマートアプリコントロールの信頼は得られません。
3. **スマートアプリコントロールを切る** — Windows セキュリティ →「アプリとブラウザーの制御」→
   「スマートアプリコントロール」→ オフ。
   **一度オフにすると Windows を再インストールするまで戻せません**。よく考えてから行ってください。

栞（`nashi.dll`）は SSP から読み込まれる DLL なので、この制限とは関係なく動きます。

## 栞のしくみ

* SHIORI/3.0 の DLL として `load` / `unload` / `request` を公開しています（`src/nashi.def`）。
* 起動時に、DLL と同じフォルダの **`ghost.json`** を読み込みます。
* SSP から来たイベント（`OnBoot`、`OnMouseDoubleClick` など）に対応するブロックを実行し、
  結果のさくらスクリプトを `Value:` で返します。
* 同じイベントのスクリプトが複数あるときは、`weight`（えらばれやすさ）で抽選します。
* `OnSecondChange` を数えて、設定した間隔で **ランダムトーク**（`kind: "talk"`）を再生します。
  直近に出したトークは候補から外すので、同じ話が続きません（外す数はゴーストの設定で変えられます。
  既定はトーク数の半分・最大 8）。出した順番は `nashi_save.json` に残ります。
* 同じイベントにブロックが複数あるときも、直前に選んだものは避けます。
* 変数は終了時（および 2 分ごと）に **`nashi_save.json`** へ保存され、次回起動時に復元されます。
* リクエストが Shift_JIS で来ても UTF-8 に変換して処理し、応答は常に UTF-8 で返します。
* イベントは大きく **はじめの1回**（`OnFirstBoot` / `OnBoot`）・**定常ループ**（`OnSecondChange`）・
  **その他のイベント**の 3 つに分かれます。定常ループは SSP が毎秒たたいてくるので、
  帽子ブロックの「◯秒ごと」で間引けます（`everySec`）。
* マウス系のイベントは、**当たった場所（あたま・かお・むね・スカート・て）と相手**で
  しぼり込めます。書き出す仮シェルにも、その名前の当たり判定を入れてあります。
* `OnMouseMove` が同じ場所で続いたら **`OnNadeNade`（なでられたとき）** を自分で作ります。
  SSP にはこのイベントはありません。栞の中で数えています。
* **ゴースト間通信**（`OnCommunicate`）に対応しています。相手の名前と言われたことで
  しぼり込めます。こちらから話しかけるときは応答に `Reference0: 相手の名前` を付けます。
  話しかけ合いが 8 往復続いたら、しゃべるだけにして通信は打ち切ります。
* しぼり込みを書いたブロックは、条件なしの同じイベントより**優先**されます。
* ブロックが未定義のイベントには、あいさつなどの控えめな既定動作を返します。
  `OnClose` では必ず `\-` を付けて、ゴーストがちゃんと終了するようにします。

### SSP なしで試す

```powershell
.\build.ps1 -Test
.\shiori\dist\test_host.exe .\output\なしちゃん\ghost\master OnBoot OnMouseDoubleClick:0,0,0,0,Head OnClose
```

`イベント名:参照0,参照1,...` の形で指定します。`OnSecondChange:0,1*200` のように `*回数` を付けると繰り返せます。

## つくれるもの / まだできないこと

できること:

* セリフ、表情（サーフェス）切り替え、間（ウェイト）、クリック待ち、バルーン切り替え
* 選択肢（`\q`）とその行き先、リンク（`\_a`）、音（`\_v`）
* 変数（好感度・フラグなど）、条件分岐、くりかえし、ランダム分岐、トークの呼び出し
* ゴースト間通信（`OnCommunicate`）— 話しかけられたときの反応と、こちらから話しかけること
* 時刻・曜日・起動回数などの情報、四則演算・比較・文字列操作
* どうしても必要なときの「さくらスクリプトをそのまま出す」ブロック

まだできないこと（必要なら `ui\js\blocks.js` と `shiori\src\interp.cpp` に足せます）:

* SERIKO のアニメーション定義、ネットワーク更新、SAORI 呼び出し
* 複数キャラ（3 人目以降）の細かい制御 — `\p[n]` は「そのまま出す」ブロックで書けます

## メモ

* 生成される仮シェルは、絵を用意するまでの繋ぎです。配布するゴーストには自分の絵を使ってください。
* PNG も .nar も外部ライブラリを使わず自前で書き出しています（zlib 不要）。
* 画面は WebView2 の中で動く HTML/CSS/JS ですが、`https://nashi.example/` という
  見せかけのアドレスから exe の中身を直接返しているだけで、通信はしていません。
